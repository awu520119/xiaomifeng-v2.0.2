# NFC 卡平台 MVP 需求清单

## MVP 目标

跑通“一张 NFC 卡购买/承载一次旅拍权益，并在出片后成为成片藏品”的最小闭环。以卡号为主键追踪状态；后台按激活卡数统计结算，并能逐卡查询。

## MVP 最小业务路径

后台建卡并生成一对一领取链接 → 线下将每张卡的专属链接写入对应实体卡 → 游客碰卡打开链接并确认领取 → 系统把卡和一次旅拍权益绑定到游客 → 游客碰现场贴片召唤 → 选择可用卡并核销、建单、记账 → 复用现有拍摄流程 → 出片后转为藏品卡 → 后台逐卡查询并按激活数对账。

## MVP 核心需求

| 序号 | 需求模块 | MVP 要求 | 验收要点 |
| --- | --- | --- | --- |
| 1 | 卡批次与线下写卡 | 后台按批次建立卡记录，为每张卡生成唯一卡号、随机领取码和专属链接，并导出写卡清单。线下写卡时先扫描实体卡 UID 或卡面序列号，再写入对应链接并回读校验；离线写卡结果可导回后台。 | 每张实体卡、卡记录和领取链接一一对应；写卡成功、失败、待处理数量可按批次查看；写卡失败的卡不能标记为已发出。 |
| 2 | 领取与激活绑定 | 游客碰实体卡打开专属链接，登录小程序并确认领取。服务端根据链接中的领取码定位卡记录，校验该卡已发出、未激活且领取码有效后，将卡绑定当前用户、发放一次旅拍权益、标记领取码已使用。 | 打开链接本身不发权益；只有确认且服务端校验成功后才绑定和发放。同一卡或领取码不能重复领取；成功激活计入激活卡数。 |
| 3 | 现场召唤 | 现场 NFC 贴片写入通用召唤入口，负责打开小程序，不读取实体卡。用户登录后，平台按当前用户查询其已绑定且有可用权益的卡。 | 无可用卡时明确提示；绑定多张可用卡时，用户可选择本次使用的卡。 |
| 4 | 核销与建单 | 用户选定卡后，一次拍摄只核销该卡的一次权益，并创建拍摄订单和核销台账，记录来源卡号。 | 核销、建单和记账可相互关联；重复点击、重试或重复请求不会重复扣权益或重复建单。 |
| 5 | 拍摄与成片 | 复用现有排队、拍摄、上传和交付流程；出片后将对应卡转为成片藏品卡。保存期限默认 1 年，支持配置。 | 成片、订单和原卡关联；游客可在小程序查看成片藏品。拍摄异常沿用现有失败处理流程，并保留卡和订单记录。 |
| 6 | 逐卡查询与结算统计 | 后台按卡查看批次、平台卡号、实体卡标识、写卡状态、激活绑定、权益核销、订单和成片状态；提供激活卡数汇总及明细。 | 汇总可下钻到逐卡记录；统计口径按成功激活卡数，且与卡的激活记录一致。 |
| 7 | 防重与留痕 | 对激活和权益核销做重复校验，并保留关键操作的时间、结果和关联对象。 | 重复激活、重复核销有明确拦截和记录，支持定位到卡及订单。 |

## MVP 规则

- 一张卡对应一次旅拍权益；权益成功核销后不能再次使用。
- 实体卡专属链接用于领取并绑定权益；现场贴片使用通用召唤链接，两者职责分开。
- 权益记录关联 `card_id`，领取链接中的一次性领取码只用于定位对应卡和完成首次领取，不直接承载权益信息。
- 三种标识不能混用：`card_id` 是平台卡记录主键；实体卡通过芯片 UID 或卡面序列号识别；领取码是链接中的一次性凭证，后台映射到 `card_id`。
- 线下写卡使用后台导出的批次清单；逐张扫描实体卡标识、写入对应链接、回读核验后记录成功/失败。离线操作时先在写卡设备加载清单，完成后将结果回传或导入后台。
- 卡状态至少区分待写卡、写卡成功待发出、写卡失败、已发出、已激活、已核销和藏品卡；写卡失败卡不能发出。
- 激活卡数是结算统计口径；统计周期、异常激活是否剔除等细则待确认。
- 成片交付后转为藏品卡，默认保存 1 年；期限可配置。
- 拍摄失败如何恢复权益沿用现有拍摄流程，不在本 MVP 另建一套失败处理机制。

## 本版不做

- 卡片转赠。
- 独立的库存盘点和补货管理。
- 丢卡追责。
- 复杂的卡权益组合和多次权益包；本版仅跑通一次旅拍权益。
- 单独建设拍摄、排队、上传或成片生产流程。

## 待确认规则

- 卡退回、作废和重新发放的处理方式；MVP 先以唯一卡号和发出记录跑通主路径。
- 激活卡数的统计周期，以及异常激活、退款或作废卡是否计入。
- NFC 卡激活是否需要用户手机号或其他身份校验。
- 线下写卡后如何确认写入结果与实体卡匹配；是否需要回传写卡成功/失败状态。
- 实体卡是否都有可读取的芯片 UID；若无，统一使用哪种卡面序列号/条码作为写卡时的实体标识。
- NFC 链接被复制或转发时是否增加卡背验证码等二次验证；当前一次性链接只能保证先领取者成功，不能单独证明领取者持有实体卡。
- 藏品卡保存期到期后的访问、续期和删除规则。
