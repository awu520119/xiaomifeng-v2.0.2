## 优惠券列表

1. **样式**：沿用现有单白卡表格、右侧新建抽屉、居中定向发券弹窗。后台菜单保留优惠券管理和发放记录，不增加三个并列记录 Tab。
2. **类型**：本期创建满减券、折扣券和体验券，显示具体优惠内容或可兑换权益，不再使用「优惠额度」统称。
3. **列表字段**：序号、优惠券名称、类型、优惠内容、可兑换商品/适用范围、生效日期、失效日期和操作。商品名称包含拍摄点，价格券范围格展示拍摄点和主题；两项日期按日期与时间两行直接可见；创建时间移至内部记录。
4. **发券入口**：每行直接提供「定向发券」「券码」「领取二维码」。三种方式对三类券都适用。点击券名查看规则及发放限制。
5. **发放条件**：已停用、已失效或总量耗尽的券不能新发放、新生成券码或新建可领取入口；未来生效的券可提前发放和领取，生效前不可核销。

## 新建优惠券

1. **名称与类型**：名称必填，最多50字；选择类型后只显示对应配置。
2. **优惠和权益配置**：

    | 类型 | 必填配置 | 使用规则 |
    | --- | --- | --- |
    | 满减券 | 订单门槛、减免金额 | 门槛大于0；减免额大于0且小于门槛，满足门槛可用一次 |
    | 折扣券 | 订单门槛、折扣 | 门槛可为0；折扣0.1至9.9折，满足门槛可用一次 |
    | 体验券 | 可兑换的主题体验商品、次数 | 至少选择一个具体商品，次数为正整数；每次核销从所选商品中兑换一次体验 |

3. **商品定义**：体验商品明确包含拍摄点与拍摄主题，例如「南长街·古韵照壁主题体验」，不是只填写泛化的「拍摄服务」。体验券的拍摄点和主题由已选商品带出，避免范围与可兑换商品矛盾。
4. **价格券范围**：满减和折扣券可选择全部或指定拍摄点、全部或指定主题；手动核销时只能选择命中该范围的商品。
5. **固定有效期**：所有券必须配置完整生效日期和失效日期，精确到秒，失效晚于生效；取消「领取后N天」口径。生成、定向发放、兑换和扫码领取均沿用同一固定区间，不重新起算、不延长截止时间。
6. **发放总量**：1至100000的正整数；每生成一张券消耗一个名额，包括直接发放、生成待兑换码及扫码领取。既有码兑换时只变更该券的领取用户，不再消耗名额。
7. **每人限领**：正整数且不超过总量；同一手机号对同一券累计领取数适用于全部三种发券方式。已使用、过期及作废的历史券仍计入；同一批手机号不得重复。
8. **补充说明**：可填写使用说明、内部备注；本地原型保留平台为默认成本承担方，不增加结算、支付或成本分摊流程。
9. **保存结果**：新增券并返回列表；已生成的券保存规则和时间快照。本期不编辑已发券的核心规则。

## 定向下发到手机号

1. **交互**：沿用居中「定向发券 - {券名}」弹窗，一个多行输入框接收一个或多个手机号；支持换行、中文/英文逗号、空格和分号分隔，最多1000字符。
2. **校验**：手机号须为11位格式；空名单、重复、任一用户超限、整批超过剩余额度或券已失效时，整批不发放；明确显示失败原因。
3. **结果**：每人生成一张有唯一券号的用户券，记录手机号及固定起止日期；成功后在当前券行展开查看。未来生效券显示未生效，不允许提前核销。

## 券码兑换

1. **入口**：点击优惠券行的「券码」后在本行展开；可生成并下载券码。每个券码对应一张实际券和一个唯一券号，不再拆成渠道凭证与另一张用户券。
2. **唯一性**：领取前后、核销和作废始终使用同一券号；码兑换后只绑定领取用户，不生成第二个券号、不重复占发放量。
3. **兑换方式**：输入券号兑换，或扫描该张券的兑换二维码进入预填券号页面。手机号用于本地模拟登录；已领取码、已作废码、已过期码不能重复兑换。
4. **二维码**：每张未领取券提供二维码预览与PNG下载；生成二维码不代表兑换或核销。详细规则见《优惠券券码与领取PRD.md》。

## 扫二维码领取

1. **领取对象**：列表「领取二维码」配置指定手机号或所有登录用户，默认指定手机号；指定模式必须填写有效、无重复的手机号名单。
2. **生成与下载**：生成独立领取入口，提供PNG下载和链接复制。每个入口保留当次名单，重新生成是新的领取入口。
3. **领取校验**：领取时校验名单、总量、每人限领、券是否停用及失效；成功后生成带唯一券号的用户券。每次成功领取占一个名额，生成入口和下载二维码本身不占名额。
4. **日期与后续**：扫码领取不改变生效及失效时间；领取结果显示券号、优惠内容及固定日期，可返回后台查看并手动核销。

## 演示边界

1. **本地闭环**：原型演示三类券的创建、三种发券方式、唯一券号、核销、作废和记录追溯；使用浏览器本地保存，同一来源下多个页面通过存储事件同步，刷新不会丢失本次演示。
2. **真实接入**：手机号输入仅模拟登录身份，不代表真实手机号验证；没有连接真实用户、订单、支付或核销服务，也不代表跨设备数据已经接入后台。实付金额为规则演示，不发起支付。
