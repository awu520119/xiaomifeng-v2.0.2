## 页面范围与数据来源

1. **页面入口**：后台「运维管理—告警中心」；也可由工作台告警面板进入，携带设备范围。
2. **业务来源**：复用《系统消息 - Sheet1（更新）.csv》的异常规则与消息内容，覆盖设备安全、拍摄通知、超时通知、配置检测、系统授权和空域安全，共 19 类。告警记录承载处置状态，站内通知承载个人已读状态；阅读通知不改变告警状态。
3. **原型边界**：当前 19 类内容、等级、责任人、通知结果及状态均使用演示数据。真实异常检测、排班匹配、通知发送及恢复自动关闭尚未完整接入；不能以演示值认定正式分级或责任人分配规则。
4. **文档关联**：详情字段见《告警详情PRD-20261102.md》；人工完成流程见《完成处置弹窗PRD-20261102.md》。本页受理及状态变化规则可独立阅读。

## 筛选与查询

1. **关键词**：输入框当前提示「搜索告警名称或设备」。匹配告警名称、告警对象名称及异常描述，去除首尾空格，不区分英文大小写；空值表示不限。当前原型输入即筛选，点击搜索或按 Enter 可重复执行当前查询。
2. **告警等级**：选项为「严重」「一般」「提示」，单选、可清空；默认不限。取值来自告警记录，正式消息类型与等级映射待确认。
3. **拍摄点**：单选、可清空，默认不限。依据告警归属拍摄点筛选；不以机场名称代替拍摄点。当前演示选项为「雁荡山」「南长街」，生产选项范围待结合权限确认；无拍摄点的系统告警在不限时可见。
4. **日期范围**：按自然日包含开始日和结束日，可清空为不限。
    - 当前原型默认及重置范围为「2026-10-27—2026-11-02」，属于演示日期，正式默认范围待确认。
    - 当前原型实际按最近发生时间筛选，但列表「发生时间」展示首次发生时间。两者并不等价，正式采用哪一个时间口径待确认，不将该差异作为已确定规则。
    - 从工作台「前往告警中心」进入时，当前原型不限定日期，以免隐藏设备历史告警。
5. **处理状态页签**：包含「全部」「待处理」「处理中」「已关闭」，默认「全部」。选择页签后与关键词、等级、拍摄点、日期和设备范围共同筛选；各条件之间为同时满足。
    - 当前页签数量来自设备范围内的全部记录及各状态记录，未叠加其他筛选项；正式是否随全部筛选条件联动待确认。
6. **设备范围**：工作台携带设备进入时，展示「设备：{设备名称}」可关闭标签；机场范围包含机场及关联无人机，独立无人机仅包含自身。关闭标签解除设备范围，保留其他条件。
7. **重置**：清空关键词、等级及拍摄点，恢复默认日期与「全部」页签，同时解除设备范围。
8. **查询结果**：无匹配时显示「暂无告警」；空结果不显示内置分页。清空或重置条件后可重新显示记录。

## 列表字段

1. **字段顺序与来源**：按下表展示；同一告警在列表与详情使用同一份业务记录。

| 字段 | 数据来源 | 展示及逻辑 |
| --- | --- | --- |
| 告警信息 | CSV 的「告警信息标题」、消息类型及告警等级 | 主行显示等级标签和告警标题，辅助行显示消息类型。标题最多展示两行，悬停可查看全文；点击标题打开详情。标题不直接使用含完整对象与变量值的通知正文。 |
| 告警对象 | 异常事件关联的机场、无人机、订单、主题或平台授权对象 | 展示对象名称或标识；机场、无人机明确显示类型。当前非设备对象辅助标记「非设备」，不得错误归为机场或无人机。 |
| 所属拍摄点 | 告警关联对象的归属信息 | 与告警对象独立成列；展示拍摄点名称。无归属的系统告警显示「—」，不拼接机场名称。 |
| 处理状态 | 告警当前处置状态 | 展示「待处理」「处理中」「已关闭」。系统恢复自动关闭时，辅助显示「已恢复，系统自行关闭」。 |
| 发生时间 | 本次异常首次触发时间 | 格式为「YYYY-MM-DD HH:mm:ss」，重复上报不重置首次发生时间。未关闭记录辅助显示「已持续 {时长}」；已关闭记录显示「处理用时 {时长}」。 |
| 责任人 | 告警当前责任人关联的系统账号和姓名 | 账号为主、姓名为辅；未指派显示「待指派」，有姓名但缺账号时账号显示「—」。通知失败时辅助显示「通知失败」。受理操作人与当前责任人是不同概念。 |
| 操作 | 当前状态 | 依下方操作规则展示；固定在表格右侧。 |

2. **时长口径**：未关闭时为当前时间减首次发生时间；已关闭时为关闭时间减首次发生时间，关闭后不继续增长。恢复自动关闭以恢复事件时间作为关闭时间。按完整分钟向下取整，不满一分钟显示「0分钟」。
    - 当前原型已关闭记录按小时、分钟展示，未关闭记录跨天时按天、小时、分钟展示；是否统一格式待确认。
    - 缺少有效起止时间或结束早于开始时显示「—」，不得借用其他样例时间、显示负时长或推算为已恢复。
3. **列表排序**：当前按最近发生时间倒序，重复触发更新最近发生时间后位置可能变化；与首次发生时间列不同。相同时间的额外排序规则未确定。
4. **分页**：默认每页 10 条，支持 10、20、50 条，显示筛选结果总数「共 {数量} 条」；切换分页不改变筛选条件。表格内部滚动，操作列固定右侧。
5. **现有交互差异**：当前原型筛选或状态变更后页码的统一回首页策略尚未显式约定；数据减少后需落在有效页，具体保留页码或回首页方式待确认。

## 列表操作

1. **受理**：仅「待处理」显示，点击出现二次确认。
    - 标题「确认受理该告警？」；说明「受理后告警将进入处理中。」；按钮「确认受理」「取消」。
    - 取消不产生变更；确认且告警仍待处理时，变为「处理中」，记录当前操作人、响应时间和受理动作，同步列表、详情及工作台。
    - 当前原型仅记录受理操作，不自动将当前责任人替换为受理人；正式是否允许代受理及是否更换责任人待确认。
2. **处理完成**：仅「处理中」显示，点击打开「完成处置」弹窗，填写处理结果后提交关闭；不能在列表直接关闭。
3. **详情**：所有状态均显示；点击行内「详情」、标题或非操作区域打开当前告警详情抽屉。操作按钮及受理确认点击不额外打开详情。
4. **已关闭操作**：仅展示「详情」，不提供再次受理或再次完成入口。当前无重新打开、删除、批量受理或批量关闭入口。

## 恢复自动关闭

1. **恢复关联**：明确恢复事件必须匹配原告警对象、异常类型及本次异常记录；恢复通知关联原记录，不新建一条待处理告警。
2. **自动关闭**：待处理或处理中告警收到有效恢复事件时，进入「已关闭」；记录恢复时间、关闭时间、关闭方式「系统自动关闭」及备注「已恢复，系统自行关闭」。恢复与关闭时间一致。
3. **记录保留**：保留首次及最近发生时间、已有受理和工单记录；时间线追加系统恢复关闭动作。已有人工关闭记录收到后续恢复事件，不覆盖原关闭时间及人工结果；重复恢复不能反复追加关闭记录。
4. **关联影响**：自动关闭不修改关联工单状态，也不自动将任一接收人的站内通知标记已读。
5. **边界**：没有新数据、数据断流或通知已读均不代表恢复；只有具有明确解除条件的类型可自动关闭。已关闭后再次异常建立新告警，短时抖动与合并窗口待确认。
6. **原型差异**：现有原型仅有恢复自动关闭样例，尚无真实恢复事件驱动；并非所有消息类型已定义恢复条件。

## 待确认事项

1. **时间查询**：筛选与排序采用首次发生还是最近发生时间；正式默认日期范围与跨时区口径。
2. **数量与分页**：页签数量是否联动全部筛选条件；筛选和页容量变化后的页码策略；未关闭持续时间刷新频率。
3. **责任及权限**：等级映射、责任人匹配和兜底对象、可见数据范围、受理与关闭权限；受理是否转为本人负责。
4. **事件规则**：重复告警合并、恢复匹配标识、各类型恢复条件、再次触发与抖动窗口。CSV 中电池高温阈值、证书触发条件及异常悬停判定仍不完整；「飞出拍摄区」正文与触发逻辑中的「飞出限飞区」存在冲突。
5. **并发变化**：确认受理或打开完成弹窗期间告警被他人处理、系统恢复或数据失效时的最终提示与刷新方式。
