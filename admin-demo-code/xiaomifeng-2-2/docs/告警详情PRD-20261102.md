# 告警详情 PRD

> 版本 v1.0　·　日期 2026-11-02

*需求场景：运维人员在告警列表中查看异常背景、责任人、通知与处置记录，查阅推荐方案，并在当前页面继续受理、完成或转工单。*

## 页面入口与展示

1. **入口**：从告警列表的行、标题或「详情」进入；携带明确告警的入口也可直接打开对应记录。以当前告警为唯一展示对象，不能混用其他记录的关闭时间或处理结果。
2. **容器**：当前页面右侧抽屉，标题「告警详情」，宽度 800px 且不超过视口；正文独立滚动，操作区固定底部。关闭抽屉返回原列表上下文。
3. **分组顺序**：「告警信息」「处理信息」「推荐处置方案」「处置时间线」。只读字段不提供编辑入口。
4. **字段去留**：不展示「首次发生时间」字段；首次发生时间仍用于列表与时长计算，不因隐藏而删除。对象字段统一为「告警对象」，位置字段统一为「所属拍摄点」。

## 告警信息字段

1. **字段定义**：每项来源及逻辑如下。

| 字段 | 数据来源 | 展示条件及业务逻辑 |
| --- | --- | --- |
| 告警名称 | CSV「告警信息标题」所对应的告警类型 | 展示标题全文；与列表标题一致，不用通知正文代替。 |
| 告警对象 | 当前异常关联的业务对象 | 名称或标识加类型标签，机场、无人机明显区分；订单、主题及平台授权不归类为设备，当前统一显示「非设备」。 |
| 告警等级 | 当前告警等级 | 「严重」「一般」「提示」，与列表一致；正式分级规则尚待确认，演示等级不作为正式标准。 |
| 处理状态 | 当前告警状态 | 「待处理」「处理中」「已关闭」；决定底部可用操作，与通知已读状态无关。 |
| 故障类型 | 当前告警类型信息 | 当前原型实际显示 CSV 的消息类型，如「设备安全」「拍摄通知」「空域安全」；若需独立技术故障分类，应另行确定，不与消息类型混用。 |
| 错误码 | 异常上报信息 | 有值才展示，无值隐藏。 |
| 所属拍摄点 | 告警对象的归属记录 | 仅显示拍摄点，无值显示「—」；不追加机场名称。 |
| 最近发生时间 | 同次异常最近一次触发时间 | 格式「YYYY-MM-DD HH:mm:ss」，重复触发可更新；与列表按首次发生时间展示的「发生时间」区别明确。 |
| 恢复时间 | 与本次异常匹配的明确恢复事件 | 已有恢复事件时显示；不得用最后上报时间推定恢复。 |
| 持续时间 | 恢复时间与本次首次发生时间 | 有恢复时间时显示，按完整分钟向下取整；当前展示「{分钟数} 分钟」。不使用受理时间作为起点。 |
| 关闭方式 | 实际关闭动作 | 已确认需区分「系统自动关闭」「人工关闭」。当前原型仅在恢复样例中独立显示系统自动关闭，人工关闭以时间线体现，独立字段尚未补齐。 |
| 处理备注 | 系统恢复关闭结果 | 自动关闭显示「已恢复，系统自行关闭」；人工结果来自完成处置提交内容，当前在时间线中展示。 |
| 异常描述 | CSV 消息内容及本次异常的实际变量值 | 有值才展示；对象、时间、电量、温度、订单号、错误原因等取自异常事件，不使用固定演示值。长内容完整换行。 |

2. **已关闭时间一致性**：关闭动作时间、记录的关闭时间及列表处理用时必须一致；处理用时等于关闭时间减首次发生时间。人工关闭无需恢复时间，不能为了展示持续时间而虚构恢复事件。
3. **已确认与原型差异**：现有恢复样例可展示恢复、持续时间及备注；人工关闭时间尚未作为独立详情字段展示，可从时间线追溯。字段不完整不代表不需记录真实关闭时间。

## 处理信息字段

1. **当前责任人**：来源于告警关联人员，显示「{系统账号}（{姓名}）」；无人负责时显示「待指派」，有姓名缺账号时账号显示「—」。受理记录中的操作人不自动等同当前责任人。
2. **响应时间**：来源于受理告警的成功动作；有值展示，无值隐藏。未经受理而系统自动恢复关闭时，不虚构响应时间。
3. **关联工单号**：存在关联时显示可点击工单号，不存在时显示「暂无关联工单」。点击后在当前页面打开关联工单右抽屉，关闭后返回告警上下文。
    - 展示关联工单编号、标题、状态、负责人、设备及创建时间；有故障描述、处理结果、取消原因或记录时分别展示。
    - 未找到工单时展示「未找到关联工单」，不以另一工单替代。
4. **飞书通知结果**：来源于本条告警的通知记录，有值才展示；失败结果使用异常文字色。当前仅演示结果文案，不提供实际发送、回执或重试入口，不能将发送文案认定真实送达。

## 推荐处置方案

1. **推荐来源**：当前原型按告警错误码是否出现在方案故障现象中、故障类型是否相同、设备类型是否相同或方案是否同时适用机场和无人机，满足任一条件即可进入候选，最多显示 3 条。
    - 当前故障类型取消息类别，未必与方案故障分类一致；设备类型匹配可能产生范围较宽的推荐。
    - 已录入的「匹配关键词」尚未参与推荐；当前也未按启停状态排除候选。关键词权重、启停及正式排序规则待确认，不能将原型简单匹配视为正式推荐策略。
2. **方案名称**：来源于候选方案，旁边显示「查看方案」；无候选显示「暂无匹配方案」，仍可受理、完成人工处置或转工单。
3. **查看方案**：在当前页面叠加打开「处置方案详情」右抽屉，不跳转方案库页面；关闭后继续原告警详情，保留列表条件。
4. **方案详情字段**：复用方案库只读内容。
    - 「基础信息」包含方案名称、适用设备、故障类型、最近更新时间，均取所选方案。
    - 「故障现象或者错误提示信息」「可能原因」来自方案对应内容，无值显示「—」。
    - 「处置步骤」来自方案维护的步骤，按顺序编号展示，不改变执行顺序。
    - 「相关附件」显示方案关联附件名称，无附件显示「暂无附件」。当前此抽屉不提供附件预览、下载或编辑按钮，不继承附件管理页全部能力。

## 处置时间线

1. **记录来源**：本次告警触发、重复触发、受理、转工单、人工完成、恢复自动关闭等实际业务动作；仅展示已发生的动作，未发生的节点不补造。
2. **信息层次**：每个节点先展示完整日期时间与操作人，再展示动作名称；有处理结果或备注时另行展示，长文字完整换行。
    - 时间取实际动作时间，格式「YYYY-MM-DD HH:mm:ss」。
    - 人工动作取真实操作人，自动动作显示「系统」；不能所有人工操作固定显示演示账号。
    - 动作与结果区分，例如动作「完成处置」、结果「{填写的处理结果}」；系统自动关闭记录「已恢复，系统自行关闭」。
3. **顺序**：最近动作在前，首次触发在后。相同时间节点的稳定顺序及历史记录只有时分秒时的补齐口径待确认，不凭空拼日期。
4. **时间校验**：恢复及关闭不能早于首次发生；人工受理和关闭的字段时间与对应节点时间一致。重复上报不重置首次发生时间；已关闭处理用时冻结，不随当前时间增加。
5. **保留规则**：系统自动关闭保留已有人工记录；关联工单不因告警自动关闭而同步完成。当前无时间线编辑、删除入口。

## 底部操作及转工单弹窗

1. **待处理**：展示「受理」；二次确认标题「确认受理该告警？」、说明「受理后告警将进入处理中。」；取消不变更，确认后进入处理中并记录响应时间、操作人及动作。
2. **处理中**：展示「处理完成」，关闭当前详情并打开「完成处置」弹窗；提交、取消等规则见独立弹窗 PRD。
3. **已关闭**：隐藏受理、处理完成及转工单操作，可继续查阅方案、工单和时间线。
4. **转工单可见性**：未关闭且无关联工单时展示「转工单」；已有工单只能从工单号查看，不重复创建关联工单。
5. **转工单弹窗**：标题「转工单」。展示说明「转工单后告警将进入“处理中”，后续可完成处置。」；负责人必选，当前优先带出告警责任人，无责任人时原型带出首位运维人员。
    - 负责人选项来自运维人员库；正式在岗、飞书绑定及可选范围规则待确认，当前不能把任意人员均视为可接收真实通知。
    - 「创建工单」在未选择负责人时不可提交；取消不创建工单。
    - 成功后带入告警名称为工单标题，带入拍摄点、机场、设备、异常描述与来源告警，保存选中的负责人；工单进入「待接单」，建立关联。
    - 待处理告警进入处理中并记录响应时间；已处理中告警保留原响应时间。记录转工单动作，更新告警责任人为选中人员，不更改首次发生时间。
    - 工单优先级当前由严重映射为高、其他映射为中，属于原型演示规则，正式映射待确认。
    - 提示「已转为工单，告警进入处理中」。不得据此声称已完成真实飞书发送。
6. **关闭与返回**：关闭方案或工单子抽屉仅返回告警详情；关闭告警详情返回列表。直接打开记录不存在、权限失效或已被更新时的反馈待确认。

## 待确认事项

1. **正式规则**：等级、责任人分配、账号权限及代受理规则；飞书结果展示口径。
2. **推荐策略**：故障分类与消息类别的映射、关键词范围、停用方案排除、匹配优先级及同分排序。
3. **时间与显示**：是否将「最近发生时间」改为「发生时间」；人工关闭独立字段的最终展示；无历史日期或无时间线时的提示。
4. **转工单**：负责人默认值、可选范围、优先级映射、重复提交和状态变化时的反馈。
