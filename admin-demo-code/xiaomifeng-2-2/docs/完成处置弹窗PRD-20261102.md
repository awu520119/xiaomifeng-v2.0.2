# 完成处置弹窗 PRD

> 版本 v1.0　·　日期 2026-11-02

*需求场景：运维人员完成告警处理后填写最终结果，关闭告警，并让列表处理用时、详情状态与处置时间线保持一致。*

## 入口与弹窗字段

1. **可用入口**：告警列表及告警详情中，只有「处理中」显示「处理完成」。点击后打开标题为「完成处置」的弹窗；待处理告警须先受理，已关闭告警不能重复提交。
2. **上下文**：从列表打开时保留原列表；从告警详情打开时，当前原型先关闭详情抽屉再展示弹窗。工作台有同类完成入口，关闭结果必须作用于同一条告警。
3. **告警名称**：只读，取本次点击的告警名称，与 CSV 的告警信息标题对应；不得显示上一次打开的记录。
4. **告警对象**：只读，取当前告警对应设备或非设备对象名称，用于核对处理对象，不允许在弹窗内修改对象。
5. **最终处理结果**：多行文本，必填，最多 500 字，显示字数统计；占位「请输入最终处理结果」。首次打开及再次打开均为空，不沿用上次未提交内容。
    - 空文本或仅含空白字符时，「提交并关闭告警」不可用。
    - 提交时去除首尾空白，保留内部有效文字和换行；不允许仅以已读通知替代处理结果。
6. **按钮及关闭入口**：主按钮「提交并关闭告警」，次按钮「取消」，同时有右上角关闭入口；取消或关闭清空输入，不改变告警状态、不追加记录。当前从详情进入后取消返回列表，不自动重新打开详情。

## 提交规则

1. **提交前提**：当前对象存在、仍为「处理中」，且结果去除首尾空白后非空并不超过 500 字。
2. **成功结果**：将本条告警变为「已关闭」，记录关闭方式「人工关闭」、当前操作人、关闭时间和最终处理结果；同一提交动作中关闭时间与时间线动作时间使用同一时刻。
3. **时间线**：增加「完成处置」动作与提交结果；时间为实际完成提交时间，操作人为本次操作者，保留之前所有触发、受理和转工单记录。
4. **处理用时**：关闭时间减首次发生时间，按完整分钟向下取整；起点不使用受理时间或最近重复触发时间。关闭后固定，不继续增长。关闭早于首次发生或缺少有效时间时不显示负时长，不套用其他样例时间。
5. **页面更新**：关闭弹窗并清空输入，提示「告警已处置并关闭」；更新列表、详情和工作台中的同一告警。原处理中筛选下该记录不再出现，可在已关闭或全部中查看。后续打开应展示已关闭及本次时间线结果。
6. **关联边界**：不改变关联工单状态，不替他人标记通知已读，不虚构恢复时间。人工处理完成不等同系统已检测到恢复；恢复信息由明确恢复事件提供。

## 系统恢复及异常场景

1. **系统自动关闭**：待处理或处理中告警收到明确匹配的恢复事件时，按已确认方案自动关闭，关闭时间等于恢复时间，备注「已恢复，系统自行关闭」，无需填写本弹窗。不得因数据不再上报而判定恢复。
2. **打开期间已关闭**：若弹窗打开后，告警被其他人完成或被系统恢复关闭，则旧表单不得覆盖原关闭方式、时间和结果；应展示最新状态。当前原型仅阻止非处理中再次提交，尚未给出完整冲突提示，提示和刷新方式待确认。
3. **记录不存在或权限变化**：不能提交到其他告警；反馈文案及是否关闭弹窗待确认。
4. **保存失败与重复提交**：不得在未成功时提示完成，或重复生成关闭记录；原型未接入真实保存失败和并发流程，失败后输入保留、重试及按钮反馈规则待确认。
5. **人工关闭后恢复**：后续恢复事件不覆盖人工关闭时间、处理人或处理结果，不重复计算已冻结的处理用时。
6. **超长与特殊内容**：上限 500 字；内部换行可在时间线完整阅读。中文、英文、表情等计数口径尚未单独约定，不将原型控件默认计数当成已确认规则。

## 原型差异与待确认事项

1. **真实接入**：当前保存及状态变更为本地演示，恢复自动关闭仅有样例；正式服务失败、自动恢复竞争及多操作人冲突尚未覆盖。
2. **权限**：哪些角色、责任人或非责任人可以完成告警，以及受理后是否必须由受理人完成。
3. **返回路径**：从详情进入后取消是否恢复原详情；点击遮罩与 Esc 是否允许直接放弃未提交内容。当前原型未提供未保存内容确认。
4. **反馈与时长**：状态冲突、对象失效、无权限、重复提交与保存失败的具体提示，以及时长格式是否统一到天、小时、分钟。
