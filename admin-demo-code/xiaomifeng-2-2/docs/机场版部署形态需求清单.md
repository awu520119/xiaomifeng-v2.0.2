# 机场版部署形态需求清单

## 目标

验证机场部署是否可以去掉 PSDK 边缘盒子，改由上云 API 控制无人机；明确可行时的部署形态、使用前提和能力边界。

## 当前阶段与排期约束

本需求当前处于技术可行性验证阶段。验证结论通过前，不进入正式功能排期，也不将“无边缘盒子控制”作为已支持能力对外承诺。

## 核心验证清单

| 序号 | 验证模块 | 验证内容 | 验收输出 |
| --- | --- | --- | --- |
| 1 | 云端控制能力 | 核对上云 API 是否覆盖机场现有控制链路所需的无人机控制能力，并标出支持、部分支持和不支持的操作。 | 控制能力对照表及不支持项清单。 |
| 2 | 接入与权限 | 验证机场、设备与云端 API 的身份关联、授权方式和权限范围，确认租户及机场之间的数据与控制隔离。 | 接入流程、权限边界和必要配置清单。 |
| 3 | 控制链路 | 验证从业务指令发出、云端 API 接收、设备执行到结果回传的完整链路，并记录延迟、成功率和适用条件。 | 可复现的端到端验证记录和可接受指标建议。 |
| 4 | 网络与部署前提 | 确认机场网络、设备联网、云端可达性及其他必要环境条件；梳理移除边缘盒子后新增或变化的依赖。 | 无盒子部署拓扑、机场侧前置条件和检查清单。 |
| 5 | 异常与安全处置 | 验证网络中断、API 超时、指令失败、设备状态不一致和人工接管等场景下的可观测信息与安全处置方式。 | 异常场景处置表；未能安全闭环的场景列为阻断项。 |
| 6 | 现有能力差异 | 对比机场现有基于 PSDK 边缘盒子的运行能力，记录切换云端 API 后的功能差异、限制和依赖。 | 现状与目标方案差异清单。 |
| 7 | 部署决策 | 汇总验证数据、风险、限制和后续工作，形成是否可去盒子的结论。 | 明确“通过 / 不通过 / 需补充验证”；仅通过后再评估正式排期。 |

## 通过条件

- 必要控制能力能够通过云端 API 完成闭环，并能确认适用的机场与设备范围。
- 关键异常场景有明确、安全且可观测的处置方式。
- 无盒子部署所需的网络、设备、权限和运维前置条件可检查、可执行。
- 形成经评审的验证结论和能力差异清单。

## 待确认事项

- 机场版涉及的无人机型号、机场型号和必须支持的控制操作清单。
- 云端 API 的服务保障、调用限制、数据区域及认证要求。
- 控制延迟、成功率、可用性等验收阈值。
- 网络中断或云端服务不可用时是否需要备用控制方式；若需要，备用方式及安全边界是什么。
- 验证环境、责任团队和评审人。
