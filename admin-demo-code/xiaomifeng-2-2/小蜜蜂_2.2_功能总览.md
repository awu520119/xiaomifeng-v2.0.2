# 小蜜蜂 2.2 功能总览

***

## M1 商业化与营收

**[01] 券与核销**｜WY｜P0｜**新建**

**Why**：发券与核销要统一记账。

**What**

1. **预期**：发券到核销跑通，各类权益核销记同一本账
2. **范围**：券成本承担方可配（收款方 / 追形 / 共担 / 均分）；含现场领券与抽奖发券；不做定时发券
3. 券的生成与发放——面额、有效期、适用点位
4. 领券与核销——使用即核销，扣权益、建订单、触发拍摄
5. 核销台账——券 / 线上 / 卡同源，记来源与归属
6. 退款——券退回账户，有效期不延长
7. 现场发券——运营展示领券码或组织抽奖，游客扫码领取
8. 防刷与全程留痕

**[02] 景区套票 · 商品与订单（含多拍摄点组合成片）｜WY｜P1｜新建**

**Why**：景区多点位一次下单，拉动多点消费。

**What**

1. **预期**：一次下单拍多点，每点当场出片，结束后再合成一支多点的
2. **范围**：限同一自然日；不做跨天 / 分次到店
3. 套票商品——新增主题类型，可选点位与档位
4. 一单多履约——按点位拆，用户不逐点付费
5. 逐点交付——每点拍完当场出该点成片
6. 联拍主题配置——同一景区内配置拍摄路线、售卖价格和全局合成模板，支持上下架
7. 小程序售卖——景区首页区分单点 / 联拍主题；详情展示点位、路线、规则、交付物和合成样片
8. 订单管理——区分联拍 / 单点订单；联拍单展示多点拍摄媒体、履约状态和流程日志
9. 联拍进度——游客可查看已拍点位、剩余次数和可拍点位，可继续拍摄或主动结束
10. 多点组合成片——拍满或主动结束后，按全局模板使用已拍素材异步合成；支持预览和下载
11. 结束与兜底——未拍部分按阶梯规则退款；主动结束后按已拍素材合成
12. 资金口径——分账隔日、按退款后净额

详细需求见《景区套票需求清单.md》。

**[03] 点位直播与线上购票核销**｜XL｜P1｜**新建**

**Why**：点位直播带来线上成交；线上已售权益要现场核销履约。

**What**

1. **预期**：直播带单 → 到店核销 → 算清归谁、钱怎么分
2. **范围**：渠道只做抖音；上架看该点位收款主体（追形才可上）；不做账号开通与内容运营
3. 直播间商品配置——券 / 玩法 / 空镜 / 景区订单
4. 直播控制台——选设备与航线、下发起飞、推流、换点位
5. 直播链接与博主推广链接——生成、授权
6. 线上购票核销主题——外部已售、到店核销
7. 运营代开单——不走支付，标来源与开单人
8. 订单归因与分成结算
9. 抖音券——上架抖音，核销后追形向景区结算打款
10. 直播素材入库——含人物画面须人工审核
11. 素材复用——空镜可跨单复用，实拍不可

**[04] NFC 卡（激活 · 权益 · 成片）｜WY｜P1｜新建**

**Why**：卡是"一次旅拍权益 + 成片收藏"的载体。

**What**

1. **预期**：一张卡承载一次旅拍权益，出片后转为成片藏品，全程可查可对账
2. **范围**：MVP 以卡为主键，按激活卡数统计；后台管理并复用现有拍摄流程；不做转赠 / 盘点补货 / 丢卡追责
3. 卡号登记与线下写卡——每张卡生成唯一领取链接，线下写入对应实体卡
4. 激活与绑定——碰卡打开专属链接，校验领取码后确认领取并绑定权益，同一卡只激活一次
5. 现场召唤——碰现场贴片打开通用小程序入口，贴片不读卡，按登录用户查找可用卡权益
6. 核销拍摄——一次权益只核销一次，建订单、记台账并防重复
7. 成片藏品卡——交付成片后转为藏品卡，默认保存 1 年且支持配置
8. 逐卡查询与对账——查看卡、激活、核销、订单、成片，并按激活卡数统计

详细需求见《NFC卡平台核心需求清单.md》。

**[05] 空镜主题 + 游客预约时段**｜XL｜**P2**｜**新建**

**Why**：C 端远程消费，并为直播提供可售商品。

**What**

1. **预期**：游客远程买一个时段的空镜拍摄，拍完推送到小程序
2. **范围**：商品是"独占"；可含日出 / 晚霞等时段；不做独立入口（挂直播间卖）
3. 空镜主题与可约时段——时段、容量、航线
4. 预约下单与远程交付
5. 时段剩余容量可见
6. 拍不成——退款 / 改期
7. 素材打标入库（景区 + 时段 + 来源）
8. 内部飞行任务三入口——履约 / 直播推流 / 补素材，不产生订单

**[06] 推广分佣与个人提现**｜WY｜P1｜**新建**

**Why**：让无主体公司的推广人（导游 / 博主 / 小商贩）带单拿分成。

**What**

1. **预期**：推广人一码带单，成交后自动分成、提现到账
2. **范围**：推广人是个人（无主体公司）；可指定景点也可不指定；分佣走微信零钱提现（汇付不支持灵活用工）；依赖 [07] 支付通道
3. 推广关系与推广码——生成、绑定、归属
4. 分佣规则——按单计佣、比例可配
5. 个人提现——微信零钱；也可对接有灵活用工资质的公司
6. 分佣台账与对账
7. 拍摄点推广的成本承担可配（共担 / 均分 / 单方承担）

详细需求见《推广分佣与个人提现需求清单.md》。

**[07] 支付通道（租户双 ID ＋ 景区商家级选择）｜WY｜P1｜新建**

**Why**：收款主体决定钱先到谁、能否上直播、能否给个人分佣。

**What**

1. **预期**：同一租户下不同景区商家各选通道
2. **范围**：租户创建时两个平台 ID 都可录入；通道按"景区商家"选；选微信时商家无法直收、分账 ≤ 30%、支持零钱提现、可上架抖音（商品为抵扣券）
3. 租户级双平台 ID 配置
4. 景区商家级通道选择
5. 通道差异约束——分账上限 / 提现 / 可上架范围
6. 与 [03] 上架校验联动

## M2 内容生产与剪辑

**[08] 常用片头片尾特效化 + 贴纸**｜XL｜P1｜**新建**

**Why**：提升成片质感与剪辑效率。

**What**

1. **预期**：常用片头片尾直接套用，贴纸能加能撤
2. **范围**：不走 AIGC；不做 AI 转场；景区 IP 走预置素材
3. 片头片尾特效化
4. 贴纸叠加与移除
5. 景区 IP 素材接入（提前生成 → 景区审核 → 内置）

**[09] 滤镜与调色**｜XL｜P1｜**新建**

**Why**：成片观感一致；游客能自己挑滤镜。

**What**

1. **预期**：成片出来后游客可自选滤镜
2. **范围**：不走算法；滤镜包买断、无按次成本
3. 可复用滤镜
4. 小程序端自选——先预览再输出

**[10] AI 辅助主题内容生产**｜XL｜**P2**｜**新建**

**Why**：提升我方模板生产效率。

**What**

1. **预期**：外部剪辑工程能导进来，AI 能出初稿
2. **范围**：依赖剪辑工程可导出、可被 AI 理解（待确认）
3. 外部剪辑工程导入并转为模板
4. AI 生成剪辑脚本（初稿 + 人工精修）

## M3 现场运营与服务

**[11] 游客失败 / 排队体验重构**｜XL｜P0｜**改造**

**Why**：每一单失败与排队都直接影响口碑与重拍率。

**What**

1. **预期**：排队可预期、失败能自助重拍；无人值守点位"碰了就有片"
2. **范围**：改造型；重拍不消耗套票点数；召唤分两种——有值守用排队、无值守用段级触发（新点位不启用排队）；无值守点位交付该段全景、不含个人特写
3. 失败与排队状态机重构
4. 排队可预期——等待提示与超时策略
5. 失败可自助重拍（程序原因）
6. 成片重拍——客户觉得不好看的，小程序申请、现场运营工作台审核通过后**免费重拍**
7. 套票多次履约入队
8. 段级触发 + 异步交付——碰一下即登记，成片推送
9. 碰完的即时反馈

**[12] 现场运营工作台**｜XL｜P0｜**改造（在现有页面新增）**

**Why**：把可下放的问题给现场，把杂活数字化。

**What**

1. **预期**：现场自己看状态、自己开单、自己处理基础告警
2. **范围**：运营开关只管现场接单 / 起飞（关闭须填原因）；运维远程控制优先；不含「事件」创建；召唤方式按点位配
3. 考勤与运营开关——打卡代替点开关
4. 工时记录
5. 核销开单——入口随拍摄点，不走支付
6. 套票履约看板——当日用户与剩余点位
7. 揽客空飞记录
8. 现场检查项
9. 告警接收与现场自助处置——带方案推送、可回填结果
10. 拍摄点召唤入口——二维码 / NFC 双通道，按点位配
11. 网页版现场喊话——接后台 TTS，网页版与云喇叭二选一，外放设备 PC / PAD / 蓝牙音响
12. 现场设备异常——第一时间触达"现场运营联系人"，处置进展回传
13. 客户端错误提示与差评同步——失败 / 异常给出可定位信息（机型 / 现象 / 时间），差评一并触发
14. 直播画面观看端——手机给客户看，或运营在后台看

## M4 平台与运维保障

**[13] 运维可观测与告警处置**｜WY｜**P0**｜**新建**

**Why**：已发生事故——"看得见"与"有人管"是同一闭环。

**What**

1. **预期**：设备看得见、告警有人管、现场问题有记录
2. **范围**：边界到"处置完成并记录"；不做备件 / 上门工单、不自动读现场群消息
3. 运维大图——设备 / 告警 / 运维数据 + 天气
4. 告警处置闭环——通知责任人、排班、状态与记录可查
5. 现场问题录入——报障录为事件
6. 处置方案库——故障分级表结构化为系统数据

**[14] 后台操作日志（审计留痕）｜WY｜P0**｜**新建**

**Why**：操作不可追溯是安全与定责盲区。

**What**

1. **预期**：谁改了什么查得到，且改不掉
2. **范围**：永久留存；覆盖景区商家 / 租户；判据 = 改线上可见状态 / 涉钱 / 涉权限
3. 记录字段——操作人、时间、对象、变更前后值、来源
4. 检索与 diff 查看（看日志本身也留痕）
5. 只追加、不可篡改
6. 高风险操作联动告警

**[15] 机场版部署形态（去掉 PSDK 边缘盒子）｜WY｜P2**｜**新建**

**Why**：机场版若去掉 PSDK 的"边缘妙算 3 盒子"，部署与维护成本下降。

**What**

1. **预期**：机场部署下不加盒子也能控制无人机
2. **范围**：仍在技术可行性验证中——思路是改走"上云 API"；验证通过前不排期
3. 上云 API 控制链路验证
4. 去掉盒子后的部署形态与前置条件

详细需求见《机场版部署形态需求清单.md》。验证通过前不进入正式排期。

**[16] 商业驾驶舱数据下钻**｜WY｜**P2**｜**新建**

**Why**：营销大屏要能逐级看到单个景点。

**What**

1. **预期**：城市 → 景点逐级下钻
2. **范围**：载体 = 营销大屏
3. 数据分层与下钻交互
4. 城市 / 景点两级口径一致

详细需求见《商业驾驶舱数据下钻需求清单.md》。

**[17] 景区合同与文档管理**｜WY｜**P2**｜**新建**

**Why**：景区合同分散存放，集中上传便于管理与留存。

**What**

1. **预期**：不同景区合同在后台统一上传、按景区可查
2. **范围**：合同与景区 / 租户对应
3. 合同上传与归档
4. 按景区 / 租户检索
5. 权限——谁能看、谁能传

详细需求见《景区合同与文档管理需求清单.md》。
