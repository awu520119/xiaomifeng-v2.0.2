运维管理 PRD

2026-10-28 · v0.1

面向运维人员和现场运营人员，集中查看设备运行状态、接收并处置异常告警、维护值班安排、管理运维工单和复用处置方案。值班安排由本系统配置，飞书负责人员身份绑定和消息触达。

v0.1 2026-10-28 初版，收敛运维大图、告警处置、值班配置、运维工单、处置方案和运营工作台联动范围

一、范围与模块边界

  1. 本期包含后台「运维管理」下的以下页面：
    • 运维工作台
    • 告警中心
    • 值班排班
    • 运维工单
    • 处置方案库
  2. 现场问题可从后台和小程序提交；小程序只负责问题录入，不承担告警处置、排班配置和方案维护。
  3. 本系统负责设备、告警、排班、工单和方案的业务状态；飞书负责人员身份绑定及通知触达，不作为本系统的排班主数据源。
  4. 同一异常不在通知中心和告警中心分别维护两套处置状态：告警中心维护问题状态，通知中心只维护发送、送达和已读状态。

二、运维工作台

1. 设备总览

  1. 展示设备总数，以及在线、离线、异常数量。
  2. 展示设备最近一次上报时间；超过系统设定的上报阈值未上报时，设备标记为离线或异常。
  3. 以设备地图或点位分布方式展示设备所在拍摄点、机场和设备状态。
  4. 支持按拍摄点、设备类型、连接状态和健康状态筛选设备。
  5. 点击设备进入设备详情，不离开当前运维模块。

2. 设备详情

  1. 展示设备名称、设备编号、设备类型、所属拍摄点、所属机场、连接状态、健康状态和最近上报时间。
  2. 展示该设备的未关闭告警、历史告警和关联工单。
  3. 展示告警处置记录，包括响应人、响应时间、处置动作、处置结果和关闭时间。
  4. 设备详情中的告警和工单支持跳转到对应详情，并保留返回入口。

3. 天气数据

  1. 在设备或机场信息区域展示设备所在地天气：天气状况、温度、风速、降水和更新时间。
  2. 天气数据与设备状态、实时告警在同一页面上下文中呈现，用于辅助判断是否存在天气导致无法起飞的可能。
  3. 天气数据不可用时，展示「天气数据暂不可用」，不得使用过期数据冒充实时数据。
  4. 天气信息只作为运维判断依据，不自动改变设备状态或告警状态。

三、告警中心与告警处置

1. 告警列表

  1. 展示告警编号、告警名称、告警等级、所属设备、所属拍摄点、发生时间、当前责任人、处理状态和关联工单。
  2. 支持按告警编号/名称/设备、告警等级、拍摄点、时间范围和处理状态筛选。
  3. 告警状态至少包括「待处理」「处理中」「已关闭」；列表支持按「全部未关闭」「待处理」「处理中」「已关闭」查看。
  4. 同一设备的重复上报应更新原告警的最近发生时间和次数，不重复生成无法区分的告警记录；具体去重窗口待确认。

2. 告警详情与处置

  1. 展示告警描述、首次发生时间、最近发生时间、当前责任人、响应时间、关联工单、通知结果和处置时间线。
  2. 「待处理」告警支持「确认响应」；确认后状态变更为「处理中」，记录响应人和响应时间。
  3. 支持将告警转为运维工单；转入后保留告警与工单的双向关联。
  4. 支持转派责任人；转派后更新当前责任人，并向新责任人发送通知。
  5. 支持关闭告警；关闭前必须填写处置结果，关闭后记录关闭人和关闭时间。
  6. 工单完成不自动关闭告警；只有告警处置人明确关闭告警后，告警才进入「已关闭」。
  7. 告警推荐处置方案根据故障类型、设备类型和错误码匹配处置方案库；无匹配结果时展示空状态，不阻断人工处置。

3. 飞书告警通知

  1. 告警产生后，优先通知当前告警责任人；没有责任人时，通知告警发生时该范围内的当日值班责任人。
  2. 告警责任人和当日值班人员必须来自本系统的运维人员库，并且已绑定飞书账号且处于「在岗」状态。
  3. 通知内容至少包含告警等级、告警名称、设备、拍摄点、发生时间、当前状态和本系统告警详情入口。
  4. 告警「确认响应」「转派」「关闭」等关键状态变化应按通知规则通知相关人员；不因每一次重复上报都发送新消息。
  5. 飞书通知失败时，告警仍正常生成，并在告警详情记录失败原因；支持人工重试或按规则自动重试。
  6. 飞书消息「已读」不等同于告警「已确认」；告警状态只由本系统处置动作改变。

四、值班排班与飞书责任人

1. 运维人员库

  1. 运维人员库维护可参与值班和告警处置的人员，不直接把姓名或手机号作为唯一身份标识。
  2. 每名人员至少包含姓名、角色、在岗状态、联系电话、可负责拍摄点/范围和飞书绑定状态。
  3. 飞书账号绑定状态至少包括「已绑定」「未绑定」「通知异常」。
  4. 排班选择人员时，仅允许选择在岗人员；未绑定飞书的人员可以保存排班的规则待确认，若允许保存，必须明确提示其无法接收飞书通知。
  5. 人员离岗、飞书账号失效或被移出应用可用范围时，不得继续作为新的值班责任人；已存在的历史排班需保留原记录。

2. 排班配置

  1. 支持按月查看和维护值班安排。
  2. 每条排班至少包含值班日期、班次、开始时间、结束时间、值班范围、主值班人员和创建/更新时间。
  3. 支持配置全局值班或指定拍摄点值班。
  4. 同一日期、同一值班范围、同一班次不得重复排班；保存时提示冲突并阻止提交。
  5. 排班新增、修改、删除后记录操作人和变更内容。
  6. 排班保存成功后，向受影响的值班人员发送飞书通知：新增通知新人员，替换时通知新旧人员，删除时通知原值班人员。
  7. 支持在值班开始前发送提醒；提醒时间和是否允许重复提醒待确认。

3. 当日责任人判定

  1. 告警产生时，按告警发生时间、拍摄点/全局范围和班次时间判断当日值班责任人。
  2. 若指定拍摄点存在值班人员，优先使用指定拍摄点责任人；否则使用全局值班人员。
  3. 若存在多个符合条件的人员，按主值班人员和备值班人员规则通知；备值班人员机制待确认。
  4. 若没有匹配排班，告警不得静默丢失，应通知运维主管或运维群，并记录「未匹配值班人员」。

五、运维工单管理

1. 现场问题录入

  1. 支持后台和小程序录入现场问题。
  2. 现场问题至少包含问题描述、发生拍摄点、关联设备、发生时间、提交人和现场照片。
  3. 拍摄点和设备应支持选择；选择拍摄点后，设备列表只展示该拍摄点下可关联的设备。
  4. 现场照片支持预览；上传失败时提示失败原因，并允许重新上传。
  5. 从告警转入工单时，自动带入告警描述、拍摄点、设备、发生时间和来源告警编号；允许补充现场照片和人工描述。

2. 工单列表

  1. 展示工单编号、标题、来源、拍摄点、关联设备、优先级、负责人、处理状态、创建时间和更新时间。
  2. 支持按工单编号/标题、拍摄点、负责人、来源、优先级、处理状态和时间范围查询。
  3. 工单来源至少包括「告警转入」「人工上报」「现场录入」；来源告警工单需展示关联告警入口。
  4. 工单状态至少包括「待接单」「处理中」「已完成」「已取消」。
  5. 列表支持按状态查看，筛选和分页变化后保持有效页码。

3. 工单流转

  1. 工单创建后进入「待接单」，可指定负责人；负责人接单后进入「处理中」。
  2. 负责人支持转派，转派后记录原负责人、新负责人、操作人和时间。
  3. 「处理中」工单支持添加处理记录，处理记录至少包含时间、操作人、动作和描述。
  4. 完成工单前必须填写故障原因和处理结果，提交后进入「已完成」。
  5. 「待接单」工单支持取消，取消前必须填写取消原因；取消后进入「已取消」。
  6. 工单完成或取消后保留完整时间线，不允许删除已产生的处理记录。
  7. 工单关联告警时，工单完成不自动关闭告警，告警仍按告警处置流程单独处理。

六、处置方案库

1. 方案维护

  1. 支持新增、编辑、查看、启用和停用处置方案。
  2. 方案至少包含方案名称、故障类型、适用设备类型、适用型号、关联错误码、故障现象、可能原因、处置步骤、注意事项和附件。
  3. 支持上传和预览方案附件；附件类型、大小限制和在线预览范围待确认。
  4. 方案状态至少包括「已启用」「已停用」；已停用方案不得作为自动推荐结果。
  5. 每次新增、编辑、启用、停用都记录操作人、操作时间和变更内容。
  6. 方案详情需展示更新时间、最近修改人和版本/变更记录；是否支持多版本回滚待确认。

2. 方案检索与匹配

  1. 支持按方案名称、故障类型、设备类型、设备型号、错误码和状态查询。
  2. 告警详情和工单详情根据错误码、故障类型、设备类型和设备型号推荐已启用方案。
  3. 推荐结果需展示方案名称和匹配依据，点击后进入方案详情。
  4. 多个方案同时匹配时，优先展示错误码完全匹配，其次为故障类型匹配，再次为设备类型/型号匹配；排序规则待确认。
  5. 无匹配方案时展示「暂无匹配方案」，不影响告警或工单继续处理。

七、与运营工作台联动

  1. 运维模块与现场运营工作台共享拍摄点、设备和任务上下文。
  2. 运营工作台发现设备异常或现场问题时，可跳转到告警中心或新建运维工单，并带入拍摄点、设备和问题描述。
  3. 运维人员在告警或工单中查看设备状态、天气和关联任务时，可回到运营工作台对应设备或拍摄点。
  4. 两个模块不重复维护设备主数据；设备名称、编号、拍摄点和设备状态应保持一致。
  5. 本期联动至少覆盖入口跳转和关键字段带入；是否需要在运营工作台直接展示告警/工单状态待确认。

八、通用权限与审计

  1. 运维相关操作至少记录操作人、操作时间、对象编号、操作动作和结果。
  2. 查看、编辑、转派、关闭告警、创建/完成工单、维护排班和维护方案应支持权限控制。
  3. 具体角色及权限范围待结合现有系统角色确认；在权限未明确前，不将所有运维人员默认视为可维护排班或关闭告警。
  4. 飞书通知发送记录、失败原因和重试记录应可在告警或排班相关详情中追溯。

九、本期验收口径

  1. 从设备总览点击异常设备，可以进入设备详情并看到未关闭告警和关联工单。
  2. 新增一条值班排班后，对应值班人员能收到飞书通知；修改或删除排班时，受影响人员收到变更通知。
  3. 告警产生后，能根据当日排班匹配责任人并发送飞书通知；无排班或发送失败时，系统有明确提示和记录。
  4. 告警可以完成「确认响应 → 转工单 → 处置记录 → 关闭告警」闭环，工单和告警状态互不错误覆盖。
  5. 后台和小程序均可录入现场问题，照片、时间、点位和设备信息可在工单详情中查看。
  6. 工单可以完成「创建 → 接单 → 转派/添加记录 → 完成或取消」闭环，并保留时间线。
  7. 处置方案可以新增、编辑、停用和检索；告警和工单能推荐匹配的已启用方案。
  8. 运营工作台与运维模块之间可以完成点位/设备上下文跳转，关键字段不丢失。

待确认事项

  1. 设备状态和“超过多久未上报”分别采用什么阈值；机场和无人机是否采用不同阈值。
  2. 告警重复上报的去重窗口、升级条件和通知频率。
  3. 值班是否支持主值班、备值班；多个全局值班人员的通知顺序和冲突规则。
  4. 未绑定飞书账号的运维人员是否允许保存排班；没有匹配值班人员时的兜底接收人或群聊。
  5. 飞书应用的可用范围、通讯录同步方式、账号绑定方式和通知卡片是否需要支持“确认响应”按钮。
  6. 飞书通知失败后的自动重试次数、重试间隔和人工重试权限。
  7. 天气数据来源、刷新频率、保留时长和是否展示飞行适宜性判断结果。
  8. 小程序录入问题时的登录身份、照片数量/大小限制和是否允许离线提交。
  9. 方案附件支持的文件类型、大小限制、预览方式和是否需要版本回滚。
  10. 运营工作台需要联动到什么深度：仅入口跳转，还是需要同步展示告警和工单摘要。
